# Starlight capabilities

Type: research

## Question

Can current Astro Starlight do what this site needs, and how? Specifically: French as the root locale with English under `/en/`; fallback to the other locale with a "not yet translated" notice; custom content collections (YAML/JSON data and MD/MDX) alongside the docs collection, with pages generated from them; Pagefind search covering French; overriding/adding page components (skill bar, gear card, duty badge); autogenerated vs hand-written sidebar; image optimisation for screenshots and handling of short video loops; deploying to GitHub Pages. Note any limits that would push toward plain Astro instead.

## Answer

**Stay on Starlight** (0.42.10 on Astro 7.4.7, pin exact versions; Starlight is 0.x, so minor releases can break). Nothing the site needs is a reason to switch to plain Astro.

- **FR root + `/en/`:** native (`defaultLocale: 'root'`, `root: { lang: 'fr' }`, `en: { lang: 'en' }`). French UI strings ship with Starlight.
- **Fallback:** built in only from the default locale. An EN visitor on a page that exists only in French gets the French content at `/en/...` with a notice (overridable `FallbackContentNotice`). The reverse direction is **not** supported: if a page exists only in English, no French route is generated, so it 404s. Recommended: a French-first rule enforced by a build/CI check. An MDX stub plus route middleware might work but is untested.
- **Custom collections:** YAML/JSON/MDX data collections sit next to `docs`, linked with `reference()`. `docsSchema({ extend })` adds frontmatter fields. Generated pages use `<StarlightPage>`, which provides the locale from the URL, the language switcher, search indexing and an `isFallback` prop. Use prefixed route folders, not a root `[...slug]`.
- **Sidebar:** generated pages can't be autogenerated. Add them as manual `link` items (locale and base are prefixed automatically) or build the sidebar from data at config time. Zone-first works as one group per Zone using `autogenerate` plus `link`s.
- **Search:** Pagefind builds per-locale indexes from `<html lang>`, and French has stemming. Caveat: EN fallback pages put French text into the EN index. Route middleware can set `pagefind = false` on fallback routes; whether to do that is a product choice.
- **Components:** overrides plus MDX components (`SkillBar`, `GearCard`, `DutyBadge`, `Loop`), reusing Starlight's `Badge`/`Card`. Content that uses components must be `.mdx`.
- **Media:** screenshots go in `src/` via `astro:assets`. Video gets no optimisation: pre-encode webm+mp4 and import from `src/` so base path and hashing are handled.
- **GitHub Pages:** `withastro/action` + `actions/deploy-pages`. `base` is **not** applied to hand-written MDX links or `public/` URLs.
- **Suggested split (not decided; for Content model, Storage mapping and Information architecture):** narrative entities (Zone, Role, Build, Build core, Duty) as `docs` MDX with extended frontmatter referencing data; Gear, Consumables and skills as YAML data collections with `<StarlightPage>` routes.
- **For the skeleton to verify:** `reference()` inside `docsSchema({ extend })`; priority of generated routes next to Starlight's `[...slug]`; the fallback-search middleware.
